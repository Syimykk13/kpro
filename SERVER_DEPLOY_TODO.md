# Server Deploy TODO

Этот файл для вечерних работ по серверу. Сервер уже используется реальным магазином, поэтому действовать только по шагам.

## Главное Правило
- Ничего не загружать и не перезапускать на сервере без явного подтверждения.
- Перед любыми изменениями сделать бэкап рабочего snapshot.
- После бэкапа сначала проверить архив/размер/наличие файла, потом обновлять код.

## Сервер
- IP: `132.243.114.107`
- Домен: `kpro.kg`
- Путь проекта на сервере: `/opt/kassa-pro`
- Основной файл данных: `/opt/kassa-pro/data/admin-snapshot.json`
- systemd service: `kassa-pro-admin.service`
- Node app слушает `5173`, Nginx проксирует домен.
- На сервере есть второй сайт `likeup.kg`; его не трогать.

## Обязательный Бэкап Перед Деплоем
На сервере:

```bash
mkdir -p /opt/kassa-pro/backups
cp /opt/kassa-pro/data/admin-snapshot.json /opt/kassa-pro/backups/admin-snapshot-$(date +%Y%m%d-%H%M%S).json
ls -lh /opt/kassa-pro/backups/
```

Желательно скачать копию на локальный компьютер перед продолжением.

## Что Нужно Будет Загрузить На Сервер
Нужно обновить серверную часть так, чтобы она поддерживала новые локальные функции кассы:

- safe-save/merge snapshot, чтобы старые вкладки не удаляли товары, ТТ, кассы и документы;
- сохранение ошибок админки/контрольки без ложного “сохранено”;
- прием sync-событий из кассы:
  - новые товары, созданные на кассе;
  - изменения цены с кассы;
  - дополнительные штрихкоды;
  - универсальные товары в чеках;
  - продажи, смены, долги, клиенты, возвраты;
- защита от дублей по id события;
- сохранение данных в правильную ТТ, группу номенклатуры и группу цен;
- запрет потери `products`, `categories`, `stores`, `registers`, `employees`, `customers`, `sales`, `debtTransactions`, `shiftReports`, `stockDocuments`.

## Что Проверить До Загрузки
Локально:

```powershell
npm run build
git status
```

Проверить, что в Git не попали:

```powershell
git check-ignore -v data/admin-snapshot.json release/K-pro-Setup-1.1.13.exe
```

## План Деплоя
1. Сделать бэкап `/opt/kassa-pro/data/admin-snapshot.json`.
2. Скачать бэкап локально или хотя бы проверить размер.
3. Собрать server package локально.
4. Загрузить код на сервер без перезаписи `data/admin-snapshot.json`.
5. Установить зависимости, если изменились.
6. Запустить `npm run build` или серверную сборку, если нужна.
7. Перезапустить service:

```bash
systemctl restart kassa-pro-admin.service
systemctl status kassa-pro-admin.service --no-pager
```

8. Проверить:

```bash
curl -I http://127.0.0.1:5173/
curl -I http://127.0.0.1:5173/admin/
curl -I http://127.0.0.1:5173/control/
curl -I http://127.0.0.1:5173/api/snapshot
```

9. Проверить в браузере:
   - `https://kpro.kg/`
   - `https://kpro.kg/admin/`
   - `https://kpro.kg/control/`
   - `https://kpro.kg/api/snapshot`

## Тест После Деплоя
- В контрольке создать тестовую кассу/ключ, убедиться, что касса не исчезает через несколько секунд.
- В админке создать/изменить тестовый товар, убедиться, что товары других магазинов не пропали.
- На кассе создать товар при неизвестном ШК, оплатить, синхронизировать.
- После `Обновить` на кассе новый товар не должен исчезать.
- Проверить, что существующий рабочий магазин видит свои товары и цены.

## Если Что-то Пошло Не Так
1. Не нажимать массово “сохранить” в админке/контрольке.
2. Остановить service:

```bash
systemctl stop kassa-pro-admin.service
```

3. Вернуть snapshot из бэкапа:

```bash
cp /opt/kassa-pro/backups/НУЖНЫЙ-БЭКАП.json /opt/kassa-pro/data/admin-snapshot.json
systemctl start kassa-pro-admin.service
```

4. Проверить сайт и `/api/snapshot`.

## Что Не Делать
- Не удалять `/opt/kassa-pro/data`.
- Не заменять серверный `admin-snapshot.json` локальным файлом.
- Не чистить очередь кассы рабочего магазина без понимания, какие продажи там лежат.
- Не трогать `likeup.kg`.
- Не выкладывать секреты банка, VPS-пароли и ключи в GitHub.
