# K-pro Project Context

Этот файл нужен, чтобы быстро восстановить контекст проекта на другом компьютере или в новом чате Codex. Обновляй его после важных изменений.

## Главное
- Проект: `K-pro`, кассовая система для розничных магазинов.
- Репозиторий: `https://github.com/Syimykk13/kpro.git`.
- Текущая версия в `package.json`: `1.1.13`.
- Стек: Electron + React + TypeScript + Vite, локальная SQLite через `sql.js`, серверный bridge/API на Node.js.
- Валюта интерфейса: `сом`.
- Язык интерфейса: русский.

## Самое Важное По Безопасности
- Один реальный магазин уже работает на системе. Любые действия с сервером делать очень осторожно.
- Сервер нельзя обновлять, перезаписывать или чистить без явного подтверждения пользователя.
- Перед любым деплоем на сервер обязательно сделать бэкап:
  - `/opt/kassa-pro/data/admin-snapshot.json`
  - желательно сохранить копию с датой отдельно.
- Не коммитить и не архивировать рабочие данные магазинов:
  - `data/admin-snapshot.json`
  - локальные SQLite-базы
  - `release/`
  - логи
  - `.env`, ключи, сертификаты, пароли, банковские токены.
- Секреты банка и VPS не хранить в репозитории и не писать в этот файл.

## Сервер И Домен
- Боевой/тестовый сервер K-pro: `132.243.114.107`.
- Домен: `kpro.kg`.
- На том же сервере есть другой сайт `likeup.kg`; его нельзя трогать.
- K-pro на сервере работает через systemd service `kassa-pro-admin.service`.
- Приложение обычно слушает локальный Node-порт `5173`, Nginx проксирует домен.
- Cloudflare используется для домена и SSL. Сейчас сайт заработал в режиме Cloudflare Flexible.

## Основные Части Проекта
- `src/renderer/` - интерфейс кассы Electron.
- `src/electron/` - Electron main/preload, локальная база, печать, COM-дисплей, sync.
- `src/admin/` - клиентская админка и контрольная панель.
- `src/shared/` - общие типы, сиды, штрихкоды.
- `scripts/admin-local.cjs` - локальный/серверный bridge для админки и API.
- `scripts/admin-data-utils.cjs` - нормализация и safe-save snapshot.
- `scripts/package-cash-installer.ps1` - сборка Windows-установщика кассы.
- `public/` - логотипы, манифесты, публичные ассеты.

## Важная Логика Данных
- Товары не должны пропадать при изменении ТТ в контрольке.
- Новая модель ТТ:
  - `NomenclatureGroup` - группа товаров и категорий;
  - `PriceGroup` - группа цен;
  - `AdminStore.nomenclatureGroupId`;
  - `AdminStore.priceGroupId`.
- Остатки всегда отдельно по торговой точке.
- Если ТТ в одной группе цен, изменение цены видно всем этим ТТ.
- Если ТТ в разных группах цен, цена меняется только для выбранной ТТ.
- `Без категории` служебная категория: видна в админке, не показывается на кассе, товары находятся через общий поиск.
- Safe-save должен защищать от старых вкладок/старых snapshot:
  - обычное сохранение не должно удалять `products`, `categories`, `stores`, `registers`, `employees`, `customers`, продажи, долги и документы;
  - удаление только через явное действие пользователя.

## Что Сейчас Особенно Хрупкое
- Серверные данные реального магазина. Перед серверными правками всегда бэкап.
- Sync новых функций с кассы на сервер: если серверная часть не обновлена, созданные на кассе товары могут исчезнуть после `Обновить`.
- Печать чеков на XP-80C/CY62K моноблоках: недавно подбирались режимы печати, отступы и кодировка.
- COM мини-дисплей покупателя: устройство на моноблоке CY62K, найден COM2; протокол может отличаться от обычного customer display.

## Как Запустить Локально
```powershell
npm install
npm run build
```

Касса:
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Start-Kassa.ps1
```

Админка:
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Start-Admin.ps1
```

Контролька:
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Start-Control.ps1
```

## Как Собрать Установщик Кассы
```powershell
npm run build
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\package-cash-installer.ps1
```

Установщики появляются в `release/`, но `release/` не коммитится.

## Как Работать С Git
```powershell
git status
git add .
git commit -m "Описание изменения"
git push
```

Перед `git add .` проверять, что не попали данные:
```powershell
git status --short
git check-ignore -v data/admin-snapshot.json release/K-pro-Setup-1.1.13.exe
```

## Правило Для Будущих Чатов
Если Codex открывается на другом ноуте или после долгого перерыва:
1. Сначала прочитать этот файл.
2. Проверить `git status`.
3. Не трогать сервер без отдельного подтверждения.
4. При серверных изменениях сначала бэкап `admin-snapshot.json`.
5. После важных решений обновить этот файл.
